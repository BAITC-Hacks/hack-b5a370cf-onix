## 3. ТЗ кейса (то, что проверяет жюри)

Пользователь получает **единый бюджет 100 у.е.**, должен принять **ровно 5 решений** из каталога 14 мер по 5 направлениям (транспорт, экология, соцсфера, безопасность, сервисы) для 5 районов Астаны (Есиль, Алматы, Сарыарка, Байконур, Нура) с 10 показателями 0–100.

**Формула (реализована в `lib/engine.ts`, не менять):**
- `I' = clip(I + Σ effect × (8 − lag)/8 + синергии, 0, 100)`
- `D_d = Σ w_k × I'_dk` (веса: T1 .10, T2 .10, E1 .09, E2 .11, S1 .11, S2 .11, B1 .09, B2 .09, C1 .10, C2 .10)
- `D_avg = Σ pop_d × D_d`
- `Score = 0.7 × D_avg + 0.3 × min(D_d) − 1 × N_crit` (N_crit — число пар район×показатель < 40)
- Синергии: M1+M2 → T1 +2 (район M1), M10+M12 → B1 +2 (район M10), M5+M6 → E2 +2 (район M5); лагом не масштабируются.
- Несовместимости: M1 и M3 (в любом районе); M4+M7 и M5+M13 нельзя в одном районе.
- Правила: ровно 5 мер, без повторов, бюджет ≤ 100, не более 2 мер из одного направления, район обязателен для районных мер.

**Контрольные числа (покрыты тестами, должны сохраняться):** база без действий **52.56**; пример ТЗ (M7, M8, M10 в Нуре + M12 + M5 в Сарыарке) **56.54**, стоимость 95; глобальный оптимум **57.24** (M2 + M3/Нура + M8/Нура + M9/Нура + M14, стоимость 98); устойчивый план **55.69** в худшем случае (M2 + M4/Нура + M8/Нура + M9/Нура + M14, стоимость 83, без событий 56.9).

**Роль AI по ТЗ (дословно):** «LLM получает результат расчёта и объясняет его, сравнивает наборы, советует. Числа он не считает и не придумывает». Это главный архитектурный принцип: **все числа считает движок, LLM только объясняет; каждое число в ответе LLM сверяется с расчётом.**

Must have (все закрыты): единый бюджет; решения по 5 направлениям; автоматический контроль превышения бюджета; AI-анализ решений; расчёт Score; объяснение сильных сторон, рисков, последствий. Опционально: сравнение результатов команд, визуализация изменений районов, AI-рекомендации, неожиданные городские события с перераспределением бюджета, одностраничный отчёт для печати в PDF вместо отдельного файла слайдов.

Критерии оценки технического этапа: соответствие и работоспособность 25, техническая реализация (архитектура, agentic AI) 25, README и воспроизводимость 25, ценность 15, потенциал и оригинальность 10. Demo Day: ценность 25, результат 20, инновационность 15, потенциал 20, презентация 20.

## 4. Стек и запуск

- Next.js 16 (App Router; production-сборка через webpack), React 19, TypeScript, Tailwind CSS 4, MapLibre GL 6. Node ≥ 22.18 (`.npmrc` с `engine-strict`). Тесты: нативный `node --test` по `.ts` (импорты с расширением `.ts`, `allowImportingTsExtensions`).
- `npm install && npm run dev` → http://localhost:3000. `npm run check` = тесты + линт + сборка + типы.
- `predev`/`prebuild` копируют воркер MapLibre в `public/maplibre/` (в `.gitignore`).
- `.env.example` описывает переменные LLM и Upstash. Без LLM-ключей всё работает, кроме советника; анализ собирает шаблонный аналитик. На Vercel без Upstash платные AI-маршруты и рейтинг закрыты.
- `/api/health` — проверка окружения (движок, активный провайдер LLM, доступность тайлов карты).
- GitHub Actions в организации `BAITC-Hacks` заблокированы биллингом GitHub («account is locked due to a billing issue»), поэтому `.github/workflows/ci.yml` лежит, но не запускается; проверки дублирует `npm run check`.

## 7. Что решили НЕ делать и почему

- **LLM не должна считать числа** (прямой запрет ТЗ) — любые «пусть модель посчитает» отклонять.
- **Модерация, загрузка фото, перекрытия улиц для кортежей** — вне ТЗ, нет данных, баллов не даст; перекрытия дорог записаны в README как потенциал развития.
- **Песочница со своими данными** — обсуждалась, не реализована (нет времени); в README есть раздел «Как подключить реальные данные».
- **«Цена справедливости»** (график всех планов средний балл vs слабейший район) и **«Голоса жителей»** — предложены, отклонены владельцем в пользу дорожной карты и стресс-теста.
- **Деплой на Vercel** — выбран позднее, но на момент аудита не завершён; локальная проверка остаётся обязательной.

## 8. Известные ограничения и риски

- Путь через Anthropic реализован по спецификации и покрыт тестом с подменой сети, но на живом ключе не проверялся (ключа нет).
- Шаблонный анализ без ключа LLM — только на русском (в интерфейсе это подписано).
- Казахские тексты написаны AI, носителем не вычитаны (`lib/i18n.ts`).
- Старые записи рейтинга без токена владения остаются доступными для чтения, но зарезервированы от изменения до административной миграции. Рейтинг принимает только планы без события.
- Первый `optimize` без прогретого кэша занимает ~0.6 с и блокирует event loop; локальный сервер прогревает кэш, Vercel считает по требованию и кеширует ответ на CDN.
- Границы районов на карте упрощены (Nominatim, `polygon_threshold=0.0003`); Байконур и Алматы — мультиполигоны с удалёнными участками.

## 9. Правила работы для следующего агента

1. Перед любым коммитом: `npm run check` (должно быть зелёным). Не ломать контрольные числа из раздела 3 — тесты их защищают.
2. Не менять `lib/data.ts` (данные ТЗ) и формулу в `lib/engine.ts`.
3. Любая новая строка интерфейса — в обе локали `lib/i18n.ts` (иначе не соберётся).
4. Любой новый вход от клиента — через `sanitizeDecisions`/`normalizeEventId` и повторную валидацию на сервере.
5. Любое новое число, которое LLM может назвать, должно быть в фактах (`factsForLLM`) или каталоге; если проверка не проходит, исходный ответ модели не отдаётся пользователю.
6. Не добавлять зависимости без необходимости; если добавил — в README раздел «Сторонние компоненты».
7. Коммиты: небольшие, с понятным сообщением на английском, минимум раз в час до 17:45. `git pull --rebase` перед пушем (в репозитории может работать сокомандник).
8. Не запускать `next build` параллельно с работающим `next dev` из другого процесса на той же папке дважды одновременно — ломается `.next`.
9. Перед публичной публикацией заменить засвеченный ключ, настроить Upstash Redis и проверить квоты платных AI-маршрутов. Пользовательские вопросы отправляются выбранному LLM API; карта загружает тайлы OpenFreeMap.
